The top level folder `raw` contains articles, ideas, webpages scraped from the web. This is the raw material to be added to the knowledge base. The user points you to an article in the knowlege base, if not, stop and ask for the source or sources.
Read the sources and give a synopsis of the content and the key findings to the user. Also check if the knowledge base contains entries that are relevant to the new data. The `kb-rank` skill (`.agents/skills/kb-rank/SKILL.md`) finds the closest existing notes for Markdown sources in `raw`; use its matches as a starting point, not as the final list. These connections between knowledge is the key. Also say which of the development objectives in `_objectives.md` the material serves, if any: material for an objective deserves more thorough treatment, such as its own note when it doesn't fit an existing one. After that discuss with the user about what needs to be updated in the knowledge base. Make updates to the knowledge base only after the user approves.
