# 2026-11-03 news

A short window of four days. The theme: **stolen credentials are now spent by machines**. Mandiant published two incident reports in which the first step is an ordinary leaked key. In the next step an agent or a resale network turns that key into money within minutes. There is also an excellent GKE post-mortem that touches three of my networking notes at once.

## Security

### LLMJacking: a leaked cloud key becomes a $100k-a-day inference bill
In [Mandiant's report](https://cloud.google.com/blog/topics/threat-intelligence/llmjacking-monetizing-compromised-cloud-models/), attackers used hijacked enterprise access to LLMs to run up more than $100,000 in charges in a single day. Some victims reached $1M before access was revoked. The model service was often *not even enabled* at the time of compromise. The attacker enabled Bedrock or the Gemini API with the stolen key, created more keys, and resold the quota through "LLM Mixers" (resellers like `jet-night.com`, which offers "unlimited frontier models" for $60 a month).

Concrete details worth acting on:
- **Initial access** came mostly through ordinary leaked identity material: Service Account keys, GitHub PATs, IAM credentials and session tokens. Last journal's backdoored Claude Code extension beaconed the names of env vars matching `KEY|TOKEN|SECRET|AWS|GCP`, which is exactly the raw material this market runs on.
- **Validation sweeps** used `max_tokens=1` requests so that stolen keys could be tested below volume-based alerts. Alert on these micro-requests, not only on spikes.
- **LiteLLM gateways** were targeted directly. CVE-2026-40217 (user ID rebind in `/key/regenerate`) turns a virtual key into `PROXY_ADMIN`. Patch your model gateway like any other internet-facing service.
- **Persistence** looked familiar: backdoor service accounts "disguised as billing optimisation utilities", SSH keys injected into instance metadata, and "burn and rotate" short-lived service accounts to get around rate limits.
- **Detection**: on AWS, watch CloudTrail for `PutUseCaseForModelAccess`, `CreateFoundationModelAgreement` and changes to `PutModelInvocationLoggingConfiguration` by non-IaC principals. On GCP, inference calls only appear in *Data Access* audit logs, which are **off by default**. Alert on `ServiceUsage.EnableService` for `aiplatform.googleapis.com`.

A timely fix on the cost side: [Google Cloud spend caps are GA](https://cloud.google.com/blog/topics/cost-management/google-cloud-spend-caps-now-generally-available/). Caps on AI services trigger within *minutes* using estimated live costs. There is now an API, so a sandbox project can get a cap at creation, and caps reset automatically each month. One catch: Provisioned Throughput is never halted. See [[Cloud well architected]] and [[AWS IAM Identity and resource based policies]]. The practical rule: deny model-invocation permissions explicitly wherever they are not needed.

### Agentic pentest frameworks in real intrusions (ARTEX, PentAGI)
[GTIG/Mandiant](https://cloud.google.com/blog/topics/threat-intelligence/artex-and-friends-enter-agentic-offensive-frameworks/) now see open-source multi-agent offensive frameworks running large parts of real intrusions. ARTEX is written in Go and has a Next.js console. Its repository was taken down, but forks such as ScopeWeaver live on. What it looks like in the logs:
- Bursts of 2–25 seconds, for example **27 events in 23 seconds** while probing AWS permissions across security groups. When it hit a "script too large" error, it trimmed the script and relaunched it within about 10 seconds.
- A classic MySQL-to-RCE pivot, run through an application's own SQL API with valid credentials:
  ```sql
  SET GLOBAL general_log_file = '/path/in/webroot/cl1217.jsp';
  SET GLOBAL general_log = 1;
  SELECT '<% ...webshell... %>';
  ```
  It iterated through `cl1217.jsp`, `f1219a.jsp`, `z1219.jsp` and so on until one compiled. One such attempt produced 240 log events. This is the same escalation path as in [[sql-injection]]: database write access combined with a web-served directory gives you code execution.
- It was noisy and full of tell-tale markers, such as files named `artex-probe-<5 digits>`. Mandiant's assessment: these tools trade stealth for speed, and they expect "fully autonomous but unsophisticated" attacks within 1–3 months.

The defensive advice is the usual list, and both this report and the LLMJacking one rely on it: short-lived scoped credentials, an isolated control plane and segmented tiers. Automation removes the time an attacker needs; it does not remove the need for a valid identity.

### ChatGPT account takeover via a maths keyboard
[Parameter Labs' chain](https://www.parameter.ai/labs/we-found-a-gap-at-openai) ([Simon Willison's summary](https://simonwillison.net/2026/Oct/31/how-we-took-over-chatgpt-accounts/)) is a textbook example for [[cross-site-scripting]] and [[HTTP Security Headers]]:
1. The MathLive virtual keyboard in the parent page accepted `postMessage()` from *any* frame, including sandboxed HTML previews, and wrote the content with `innerHTML`.
2. `innerHTML` does not execute `<script>`, but it can insert a new iframe *without* sandbox restrictions.
3. The CSP blocked inline scripts but allowlisted YouTube, and YouTube's oEmbed endpoint reflected attacker JavaScript.
4. The result was JS execution on chatgpt.com. A shared link could exfiltrate the data of any signed-in visitor.

Lessons: check `event.origin` and `event.source` in every message handler, and remember that a CSP host allowlist is only as strong as the weakest reflecting endpoint on those hosts. The bounty was $5,000.

## Kubernetes: three bugs, one timeout
[When the Kubernetes API went silent](https://cloud.google.com/blog/products/networking/the-three-layer-gke-network-mystery/) is the best read of the period. Pods in a Private Service Connect–based GKE cluster intermittently timed out against the API server. About 800 developers were blocked for weeks. The request path was: pod → PSC endpoint (NAT, adds a **proxy protocol** header) → internal passthrough NLB → control-plane VM → Envoy → kube-apiserver. This is the same path described in [[Private service connect]] and [[X-Forwarded-For and proxy protocols]].

Three independent bugs had to line up:
1. **Reordering in PSC.** The first packet of a flow takes PSC's slow "miss" path, which adds the proxy header and NAT state, and the rest take the fast path. As a result, a client FIN could arrive *after* the server's own FIN/ACK exchange.
2. **Envoy's half-close.** Envoy calls `shutdown(SHUT_WR)` and keeps holding the socket. `tcp_fin_timeout` only applies to *orphaned* sockets, so a half-closed socket held by a process can stay in `FIN_WAIT_2` indefinitely. This is a general gotcha for any proxy.
3. **A kernel bug in 6.1–6.9.6.** `tcp_ack()` returned 0 for an "old but acceptable" ACK under RFC 5961, so the reordered FIN was silently discarded.

Then the trigger: PSC's NAT makes source-port reuse (the same 5-tuple) common. When a new SYN hits the stale socket, the kernel answers with an RFC 5961 **challenge ACK**, expecting the client to RST and retry. A PSC security fix had begun dropping those ACKs as "invalid", so the handshake never completed. The first clue was Wireshark's *"TCP Port numbers reused"* flag.

Fixes: the PSC change was rolled back, then replaced with proper handling and a PacketDrill regression test. The upstream kernel fix is `795a7dfbc3d9` (*"net: tcp: accept old ack during closing"*, Eric Dumazet), backported to 6.1.y and 6.6.y and shipped in GKE 1.33.5+. What cracked the case was taking packet captures *simultaneously* at three points: the host NIC, the VM NIC and inside the container. See [[Kubernetes networking]].

## Cloud

**AWS**
- **[Lambda queues for Kafka](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-queue-kafka-esm/)** for self-managed Kafka and Confluent event sources. It builds on KIP-932 *share groups* (Kafka 4.2+). Set `ConsumptionMode: Queue`, and several pollers then consume the *same* partition, each with up to 10 concurrent invocations, with no need to over-partition. Ordering is lost. This blurs the queue/bus distinction in [[Buses and Queues]]: Kafka can now behave as a point-to-point work queue.
- **Post-quantum visibility.** CloudFront can now forward [`CloudFront-Viewer-TLS-Details`](https://aws.amazon.com/about-aws/whats-new/2026/10/cloudfront-viewer-isp-post-quantum-visbility/) (key exchange, signature scheme) and `CloudFront-Viewer-ISP` to the origin through an origin request policy, so you can measure what share of clients actually use PQC. [MSK now supports TLS 1.3](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-msk-tls/) through named security policies (1.2+1.3 or 1.3-only). This continues the Aurora `ssl_groups` thread from the last entry.
- **[Inspector scans AMIs](https://aws.amazon.com/about-aws/whats-new/2026/11/ec2-amis-scanned-through-inspector/)** without launching them. Combined with *Allowed AMIs* and declarative policies, this lets an organisation refuse to launch images that fail the scan. See [[AWS EC2]].
- **[AWS for Fluent Bit 3.0.0](https://aws.amazon.com/about-aws/whats-new/2025/10/aws-fluent-bit-3-0-0-based-4-1-1)** (Fluent Bit 4.1.1 on AL2023) adds native OTLP ingest and forwarding with SigV4, plus minimum TLS version and cipher controls on outputs. Upgrade by bumping the FireLens or DaemonSet image tag. See [[Logging in kubernetes]].

**Google Cloud**
- **[GKE CPU startup boost](https://cloud.google.com/blog/products/containers-kubernetes/gke-cpu-startup-boost-faster-pod-starts-lower-costs)** (preview) uses *in-place pod resize* to give containers extra CPU during initialisation and shrink them back without a restart. Cold starts are up to 2x faster for JVM-style workloads, without permanently over-requesting. See [[kubernetes pod scheduling]].
- **Cloud SQL for PostgreSQL**: PSC is now the *default* private IP option for new instances in new projects, and managed connection pooling works on PSC instances ([Data Cloud roundup](https://cloud.google.com/blog/products/data-analytics/whats-new-with-google-data-cloud)). See [[Private service connect]].

## Tooling
- **[NixOS idling at 96 MB](https://lowendspirit.com/discussion/11543/shrinking-nixos-ram-footprint-and-resource-requirements-to-the-bare-minimum)** on a 512 MB VPS, and still able to rebuild itself. It includes the full config. The best tricks:
  - `transparent_hugepage=never`: with THP enabled, the kernel raised `vm.min_free_kbytes` to 41 MB of reserved memory you can never use.
  - The `sysctl.` prefix matters: `mem_profiling=never` does nothing, `sysctl.vm.mem_profiling=never` works.
  - Use zram (zstd) with `vm.swappiness = 180` and `vm.page-cluster = 0`. Tuning the Boehm GC that Nix evaluation uses (`GC_INITIAL_HEAP_SIZE`, `GC_FREE_SPACE_DIVISOR=8`) is what makes `nixos-rebuild` fit in 512 MB.
  - `services.openssh.startWhenNeeded = true` makes sshd socket-activated.

  These are useful well beyond my desktop use in [[nix]].
- **Python 3.15 and uv**: [if in doubt, delete `uv.lock`](https://simonwillison.net/2026/Nov/1/delete-uv-lock-first/). A stale lock can pin a dependency that has no 3.15 wheel yet, and the build then fails in PyO3 or maturin.

## Agents in practice
- **[Spawn](https://simonwillison.net/2026/Oct/29/how-i-built-the-most-ai-pilled-company-in-the-world/)** is built by a swarm of agents that ship to production every hour, at a token cost of $3M per month. An hour without a deploy is a SEV-0, rollback takes 30 seconds, and they break things on purpose to test the recovery paths. Their cautionary tale: when GPT-6 Astra was asked to apply a security review, it "made the insecure things secure by turning them off", meaning every feature. This is [[site reliablity engineering]] taken to an extreme, and it only works because the stakes are a game.
- **[llm 0.37](https://simonwillison.net/2026/Nov/2/llm/)**: Simon Willison took fixes from 12 mostly AI-assisted contributors. He treats such PRs as "bug reports with attached examples" and triages them with a model.
- **[Resisting cognitive surrender](https://knlb.dev/essays/surrender)**: an essay on how accepting agent output uncritically quietly *reduces* your familiarity with your own system. The tech debt bites later than the productivity gain shows up.
