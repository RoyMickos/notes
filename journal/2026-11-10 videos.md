# 2026-11-10 videos

The NDC Oslo 2026 playlist: 61 talks, 60 screened. It is a broad conference with a heavy AI streak. About a third of the talks touch agents or AI-assisted coding, but most of those are opinion, keynote-style framing or vendor tours. The substance sits in a few places: one excellent event-versioning talk, two agent-security talks, a supply-chain incident review, and one experience report that is almost a mirror of how this vault works. None of the talks closely matched an existing note (best `kb-rank` relevance 0.35), so everything below is new material next to what I already know.

## Watch

### Change is inevitable: versioning event-driven systems (Laila Bougria, 1:02)
The best match for **objective 2 (event-driven systems)**. It covers public vs private events and the summary-event pattern, the schema compatibility modes (forward, backward, full, transitive) and when each suits a broker or an event store, the dual-publish and subscription-swap upgrade order on Azure Service Bus, and xRegistry deprecation events for consumers you don't know about. Related: [[Service mesh#How does this relate to event busses?|Service mesh: event busses]], [[Event-carried state transfer in Microservices]], [[Cloud event distributions and automations]].
Best parts: [12:08](https://www.youtube.com/watch?v=kCtal3G1vkE&t=728s) in-flight and error-queue messages, [18:18](https://www.youtube.com/watch?v=kCtal3G1vkE&t=1098s) public vs private events, [48:05](https://www.youtube.com/watch?v=kCtal3G1vkE&t=2885s) upgrade procedure, [55:00](https://www.youtube.com/watch?v=kCtal3G1vkE&t=3300s) xRegistry. ### Demand-Driven Context: What 300 Incidents Reveal About Tribal Knowledge (Raj Navakoti, 37 min)
**Moved up from MAYBE (6).** It serves **objective 4 (AI-augmented systems)** and describes the same design as this knowledge base. An SRE incident agent failed when fed all of Confluence through RAG. It worked once it was run over clustered past incidents (300 collapsed to about 20 types) and asked for the knowledge it lacked: 46 entities over nine batches. A "propose-knowledge" skill then opens pull requests against the knowledge repo, behind a human review gate. The tool marked the talk down as anecdotal, but the numbers and the method are concrete. Related: [[site reliablity engineering|Site reliability engineering]], [[AI Prompting]].
Best parts: [15:50](https://www.youtube.com/watch?v=n2dQVqr-0FU&t=950s) demand-driven context, [18:36](https://www.youtube.com/watch?v=n2dQVqr-0FU&t=1116s) batch results, [21:51](https://www.youtube.com/watch?v=n2dQVqr-0FU&t=1311s) clustering first, [29:09](https://www.youtube.com/watch?v=n2dQVqr-0FU&t=1749s) propose-knowledge skill. ### Applying the OWASP Top 10 for Agentic Applications to Your AI Agents (Will Velida, 1:11)
**Objective 4**, plus security. It walks through each agentic risk with a real incident and a mitigation: MCP tool-description rug pulls, chains of individually valid tools that leak data (the argument for execution-level policy over access control), memory poisoning, and cross-agent trust. The talk is long and partly a threat catalogue, so watch the segments. Related: [[AI Discernment]], [[Cloud well architected]].
Best parts: [5:50](https://www.youtube.com/watch?v=mUHG5mA9Z7I&t=350s) rug pull, [25:50](https://www.youtube.com/watch?v=mUHG5mA9Z7I&t=1550s) tool chaining, [37:00](https://www.youtube.com/watch?v=mUHG5mA9Z7I&t=2220s) cross-agent trust, [56:00](https://www.youtube.com/watch?v=mUHG5mA9Z7I&t=3360s) memory quarantine. ### How Worms Exposed the Real Attack Surface of Open Source (Charlie Eriksen, 57 min)
This one qualifies as a **security issue in tools I use**: npm, GitHub Actions and VS Code extensions (the skills in this repo install from npm). It covers last year's worms (Shai-Hulud, Glassworm, the TeamPCP attacks on Trivy, LiteLLM and TanStack) and the structural lessons: install-time lifecycle scripts, mutable tags, CI and workstations as targets, and VS Code extensions auto-updating with no recall. The practical takeaways are release cooldowns and trusted publishing. Related: [[Information disclosure]], [[Web Security]].
Best parts: [7:55](https://www.youtube.com/watch?v=9QaidOZ4zUM&t=475s) dependency graphs as transmission graphs, [44:55](https://www.youtube.com/watch?v=9QaidOZ4zUM&t=2695s) VS Code extensions, [47:43](https://www.youtube.com/watch?v=9QaidOZ4zUM&t=2863s) cooldowns, [49:16](https://www.youtube.com/watch?v=9QaidOZ4zUM&t=2956s) trusted publishing. [Video](https://www.youtube.com/watch?v=9QaidOZ4zUM) · [[raw/video/2026-11-10 videos/How Worms Exposed the Real Attack Surface of Open Source - Charlie Eriksen - NDC Oslo 2026|note]]

### A practical introduction to Domain Storytelling (Haimanot Tekie, 42 min)
**Moved up from MAYBE (5).** It is the only talk on **objective 1 (consulting skills: facilitation)**. The tool marked it down as introductory, but for this objective an introduction is the point. It shows how to scope a session (granularity, as-is vs to-be, human vs digital), why discovering with two or three people and refining with the wider team worked better than large groups, and why the conversation during drawing matters more than the diagram.
Best parts: [15:30](https://www.youtube.com/watch?v=wHr5qtdgHFA&t=930s) scoping, [30:00](https://www.youtube.com/watch?v=wHr5qtdgHFA&t=1800s) real session, [34:30](https://www.youtube.com/watch?v=wHr5qtdgHFA&t=2070s) group-size lessons. ### Socio-technical API patterns (Einar Høst, 50 min)
It sits next to objective 1: APIs as agreements between teams, and the power dynamics behind them. It covers bilateral vs unilateral design, documentation vs contract, and named anti-patterns (millstone, leech, sock puppet) with ways to prevent them. It is conceptual, but useful vocabulary when leading a customer through integration decisions. Related: [[North-South vs East-West communication]], [[Testing strategy]].
Best parts: [19:22](https://www.youtube.com/watch?v=OGO5hRw0ub8&t=1162s) bilateral design, [22:18](https://www.youtube.com/watch?v=OGO5hRw0ub8&t=1338s) contract as neutral territory, [28:12](https://www.youtube.com/watch?v=OGO5hRw0ub8&t=1692s) millstone.
